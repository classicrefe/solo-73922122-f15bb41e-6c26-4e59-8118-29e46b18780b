# 量具重复性与再现性（GRR）分析

机加工车间量具评估小工具：Flask 网页 + SQLite 保存一场试验。
登记检验员与样件 → 网页录入每人每件两次毫米读数 → 读数齐全后自动做
带交互项的双因素方差分析 → 样件磕伤可原位置换件，只重测新件，旧报告转历史备查。

## 功能

- **登记试验**：2～4 名检验员、3～8 件样件（一次只保存一场试验）。
- **读数录入**：每人对每件测两次（毫米）。同一测次原值重报只记一次；异值退回；非法数值退回。
- **方差分析**：读数齐全才计算。列出重复测量（重复性）、检验员（再现性）、
  样件×检验员交互、样件的方差分量，负分量按零计；附 SS/df/MS 表与所用读数。
- **缺测提示**：试验台与报告页均列出待补项（位置/编号/检验员/测次）。
- **换件复测**：原位置换入新编号，旧件下线、读数保留备查，现行报告转历史；
  旧件迟到读数拒收，其他样件已打开的表单仍可提交；只需重测新件。
- **两地合算**：同一把量具在两个车间各自试验后，在报告详情页（现行或历史均可）
  下载统计摘要交给对方，或上传对方摘要进行合算。摘要只含样件位置、编号与
  每格（样件×匿名检验员槽位）的次数/和/平方和，不含检验员姓名、逐人统计与逐次读数。
  只纳入位置与编号都相同的样件，两地检验员分别计数；合算结果列出参与样件与
  四个方差分量，数值与把两地对应明细放在一起做方差分析一致。
  共用样件不足 3 件或摘要无效时提示原因，原报告保留不变。
- **一致性**：样件、读数、现行报告对应同一已提交状态（单事务提交）；
  提交失败整体回滚，原进度保留。

## 本地运行

```bash
pip install -r requirements.txt
python run.py                 # http://localhost:8000
DEMO_SEED=1 python run.py     # 载入演示数据（3 人 × 5 件，报告已生成）
```

## Docker Compose 演示（换件复测 + 两地合算）

```bash
docker compose up --build     # http://localhost:8000
```

首次启动自动载入演示试验（读数齐全、现行报告已生成）。在网页上演示换件复测：

1. 打开 <http://localhost:8000> ，点「现行报告」查看既有方差分量。
2. 回到试验台，在「样件更换」选位置 3（P-103），输入新编号 `P-103B`，换入新件。
3. 报告页出现 6 项待补项（3 名检验员 × 2 测次），其余样件读数不受影响。
4. 在录入表格填入新件 6 个读数并提交（旧件 P-103 的迟到读数会被拒收）。
5. 读数齐全后自动生成新现行报告；「历史报告」中旧报告标为历史，
   点开仍可查到当时所用读数。

接着演示「换过样件后的两地合算」（报告 #1 扮演另一车间的试验）：

1. 打开「历史报告」，点报告 #1「查看」进入详情页，点「下载本报告统计摘要」
   保存 JSON 文件（此即另一车间交来的摘要）。
2. 再打开报告 #2（换件后生成的现行报告）详情页，在「两地合算」处上传刚下载的
   摘要并点「合算」。
3. 合算结果页列出参与合算的 4 件样件（位置 1、2、4、5；位置 3 因换过件
   编号不同而不纳入）、3+3 名检验员（两地分别计数）与四个方差分量，
   数值与把两地对应明细放在一起做方差分析一致。
4. 若上传无效文件、本报告自身摘要或共用样件不足 3 件的摘要，页面提示原因，
   原报告保留不变。

## 自测

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q
```

## 结构

```
grr/
  app.py      Flask 路由（试验台/读数/换件/报告/历史/两地合算）
  service.py  业务逻辑与事务（登记、录入、换件、报告生成、摘要与合算）
  anova.py    带交互项的双因素方差分析（逐次读数与汇总量两条路径共用同一公式）
  db.py       SQLite 连接与表结构
  seed.py     演示数据
  templates/  页面模板
run.py        启动入口
tests/        pytest 关键流程自测
```
